TL;DR

The branch began as a question — “can we learn anything from FluidVoice?” — and grew into a methodical hardening pass plus one real feature:

  • Audited the whole codebase with a 10-agent sweep, recorded findings, and fixed real defects in dictation, read-aloud, launchers, GNOME integration, and the installer.
  • Hardened the tests — replaced vacuous/broken tests with behavioral coverage and removed unreachable “prototype” code into an isolated experiments/ archive.
  • Modernised GNOME — ported the Shell extension to the ESM API so it loads on GNOME 45–48.
  • Shipped a pluggable ASR layer — faster-whisper stays the default; NVIDIA Parakeet is an opt-in engine behind a tiny interface, selectable via STT_ENGINE / --engine, with a WER benchmark harness for the LATAM-Spanish validation gate.

Everything is committed and pushed; the suite is green and uv sync --locked passes.

2 · Correctness fixes: STT / TTS / launchers commit d5b630c · fix

Robustness & safety

  • SSRF guard on URL-fetching paths.
  • Race conditions in the dictation capture/transcribe loop fixed; the audio queue is bounded so a slow transcription can’t grow memory without limit.
  • Resource leaks — the ffmpeg capture process is always terminated, never orphaned, even on Ctrl-C finalize.

Hard limits & clean failure

  • Absolute utterance/buffer ceilings (STT_MAX_UTTERANCE_SECONDS, STT_MAX_BUFFER_SECONDS).
  • Atomic, private status writes (0o600) so secrets/transcripts aren’t world-readable.
  • Actionable error messages for missing clipboard tools, ffmpeg, and audio backends.

3 · GNOME: correctness fixes + ESM port commits a06c3ab, d45285c · fix feat

First the integration was made honest and non-blocking; then the extension was rewritten for modern GNOME.

  • Async status — the panel reads the dictation status from a JSON file via Gio on a timer, instead of blocking the compositor with spawn_sync.
  • ESM rewrite — moved off the removed imports.* API to import … from 'gi://…' + export default class extends Extension; metadata.json now declares shell-version ["45","46","47","48"].
  • The GNOME-46 notification API change (positional args → options object) is feature-detected so one file works across 45–48.
  • Full disable() cleanup — indicator destroyed, timer removed, pending I/O cancelled — no leaks across enable/disable.
Needs a real GNOME 45–48 session to validate (GNOME Shell can’t run in CI): load/enable, notifications on both API paths, status updates, and disable/re-enable leak checks.

7 · The headline feature — pluggable ASR + NVIDIA Parakeet commits 628c45a, 5934a48, 260c5e5, 8e581d1 · feat

Inspired by analysing FluidVoice (macOS-only, can’t be reused) — but its two portable ideas can: a model-abstraction layer, and Parakeet as a natively-punctuated alternative to Whisper. Implemented in three independently-mergeable phases.

The seam

The pipeline was already engine-agnostic at both ends — audio in, text out. The model was the one hardcoded spot. A tiny protocol isolates it:

🎙 mic
→
ffmpeg
16 kHz mono
→
WebRTC VAD
→
ASR engine
faster-whisper · Parakeet
→
clipboard / typing
The highlighted box is the new ASREngine seam (src/stt/asr_engine.py). The VAD loop, capture, status, and output callback are untouched.
# the entire contract
class ASREngine(Protocol):
    def transcribe(self, audio: np.ndarray, language) -> str: ...

Phase 1 Abstraction

Extract the protocol + FasterWhisperBackend + a create_engine() factory; route the session through it. Zero behavior change, no new deps — the faster-whisper transcribe path is byte-identical.

Phase 2 Parakeet

ParakeetOnnxBackend via the MIT onnx-asr runtime; engine selection through STT_ENGINE/--engine; an opt-in stt-parakeet extra (not in all); setup-model integration.

Phase 3 Validation tooling + docs

A dependency-free WER benchmark harness (src/utils/asr_benchmark.py) scores faster-whisper vs Parakeet on a JSON manifest (per-accent WER + latency, resilient to a missing engine or a bad clip), plus quickstart, config, and attribution docs.

The doc’s one open question — does onnx-asr accept a numpy array? — was settled by introspecting the real onnx-asr 0.11.0: recognize(float32_array, sample_rate=16000) → str. No temp-WAV path needed.

Using it

# default — unchanged
./bin/talk2claude-faster

# opt in to Parakeet (Python ≥3.10)
uv sync --locked --extra stt --extra stt-parakeet
./bin/linux-speech-tools-setup --parakeet        # prefetch ONNX model (~640 MB)
STT_ENGINE=parakeet ./bin/talk2claude-faster     # or: --engine parakeet

LATAM-Spanish gate (design §6). faster-whisper stays the recommended default — Parakeet v3’s Spanish leans European/Castilian. The benchmark harness is built and tested, but its execution needs real recorded LATAM audio + the model download, so it’s a documented manual gate: Parakeet stays “experimental for Spanish” until it passes (mean WER within ~1 point of faster-whisper, no code-switching regression).
