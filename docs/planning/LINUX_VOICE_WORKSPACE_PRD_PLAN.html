Purpose / Problem

The repository contains capable dictation, read-aloud, safe insertion, GNOME focus identity, ASR abstraction, and one repository-aware Codex slice. Those capabilities are exposed through separate commands and state models. The user does not yet experience them as one coherent product or one continuous voice workspace.

The goal is a complete standalone baseline with four bounded modes—Dictate, Ask, Act, and Read—and a differentiated layer for explicit active-work context, agent-session continuity, target-bound delivery, and approvals.

Outcome: one install, one top-level CLI, one inspectable session model, and one safe path from speech to context to intent to delivery or action to visible or spoken result.
Non-outcome: this is not a notes database, meeting product, generic agent runtime, screen-history recorder, cross-platform suite, or attempt to reproduce every competing backend.

Product Principles and Invariants

  1. Four modes only. Every user action is Dictate, Ask, Act, or Read.
  2. Explicit context. Every context item has a provider, sensitivity, permission, freshness, and bounded payload.
  3. Ask is not Act. Asking cannot silently transition into execution, insertion, sending, deletion, or modification.
  4. Target binding. Direct text delivery remains bound to a stable original target. Drift or ambiguity fails to a non-inserting path.
  5. No silent consequential actions. Execute, send, delete, and modify require a visible approval artifact by default.
  6. Local by default. Audio and context do not leave the machine unless the selected provider and permission explicitly allow it.
  7. Provider replacement. ASR, TTS, agent, and history providers are adapters; the product owns session and policy.
  8. Privacy-safe state. Status, metrics, logs, and reports omit transcripts, selection contents, window titles, raw stable identifiers, secrets, and child command details.
  9. Bounded work. Input, output, subprocesses, sockets, model calls, files, histories, and retries have explicit limits and cancellation.
  10. Evidence before parity claims. Ubuntu GNOME, Spanish quality, insertion reliability, and competitor comparisons require reproducible hands-on evidence.

User Modes and Requirements

Dictate

Convert speech to text for the verified active application.

  • Hotkey and CLI start/stop
  • Visible listening, recording, processing, and failure state
  • Local faster-whisper default; optional Parakeet
  • Target-bound insertion with clipboard or overlay fallback
  • Technical and repository vocabulary
  • No automatic submit after ambiguous delivery

Ask

Ask an existing agent about explicitly selected active-work context.

  • Preview context manifest before dispatch
  • Default read-only agent run
  • Stream bounded progress and final response
  • Return visually, to clipboard, or through TTS
  • Preserve or explicitly create an agent session

Act

Request a consequential operation through an external agent or tool.

  • Separate draft and proposed-action phases
  • Visible destination, context, and operation
  • Capability-specific approval
  • Cancellation and bounded execution
  • Local metadata-only audit record
  • No send/delete/write by default

Read

Read or explain selected, visible, attached, or fetched content.

  • Selection, URL, PDF, EPUB, file, and stdin
  • Pause, resume, skip, stop, and progress
  • Summarize or explain before speech
  • Interrupt speech and preserve the session
  • Route code visually and explanations audibly

Approach

Build a thin product layer above the existing speech and delivery modules. Preserve current commands as compatibility aliases while a new lst CLI routes the four modes through a shared SessionManager and VoiceSession. Begin in-process, then host that exact same manager in an opt-in private user daemon once contracts and cancellation semantics are proven. Standalone and daemon operation must never become two policy implementations.

Use a typed, versioned local protocol. Keep raw content in memory or private ephemeral files; serialize only bounded user-authorized payloads. The daemon never becomes an agent runtime: it invokes adapters and applies policy.

Alternatives rejected

  • Thin Vocalinux plugin: loses standalone baseline and makes the discovery path depend on another installation.
  • OpenWhispr fork: imports notes, meetings, cloud, Electron, and cross-platform ownership without supplying the differentiating safety layer.
  • New general agent runtime: duplicates mature agent/session/tool ecosystems.
  • Daemon first: multiplies lifecycle and protocol risk before the domain contract is stable.
  • IBus preedit first: does not solve original-target proof and already failed the Stage 0 input-source invariance gate.
  • One command per new feature: preserves the toolbox fragmentation this plan is intended to remove.

Core Contracts

class VoiceMode(str, Enum):
    DICTATE = "dictate"
    ASK = "ask"
    ACT = "act"
    READ = "read"

@dataclass(frozen=True)
class ContextItem:
    kind: str
    provider: str
    sensitivity: str
    captured_at: float
    expires_at: float
    content: str
    metadata: Mapping[str, str]

@dataclass(frozen=True)
class ContextSnapshot:
    snapshot_id: str
    fingerprint: str
    target: TargetContext
    items: Tuple[ContextItem, ...]
    permissions: FrozenSet[str]

@dataclass(frozen=True)
class ApprovalRequest:
    request_id: str
    capability: str       # insert, execute, send, modify, delete
    destination: str
    summary: str
    expires_at: float

class AgentAdapter(Protocol):
    def capabilities(self) -> FrozenSet[str]: ...
    def discover_sessions(self) -> Sequence[AgentSession]: ...
    def send(self, request: AgentRequest) -> AgentRun: ...
    def stream(self, run_id: str) -> Iterator[AgentEvent]: ...
    def cancel(self, run_id: str) -> None: ...

class VoiceSession:
    def capture_context(self, request: ContextRequest) -> ContextSnapshot: ...
    def accept_transcript(self, text: str, revision: int, final: bool) -> Result: ...
    def dispatch(self) -> Result: ...
    def approve(self, request_id: str) -> Result: ...
    def cancel(self) -> Result: ...
    def close(self) -> None: ...

Python 3.8 compatibility means concrete generic types use typing.List, Tuple, and related forms in production even where the conceptual examples use modern notation. The snapshot target is internal authorization metadata; adapters receive only explicitly shareable context items. The fingerprint binds approvals to immutable context without persisting content.

AgentAdapter.send() is non-blocking, stream() produces exactly one terminal final/error/cancelled event, and cancel() is idempotent and terminates the complete owned process group. The current blocking Codex run() remains a compatibility wrapper until migration is complete.

State and Permission Model

Use separate lifecycle and activity axes. This prevents mode-specific work such as recording, agent execution, and speech playback from becoming mutually inconsistent lifecycle states.

AxisClosed valuesPurpose
Lifecyclepending, running, awaiting-approval, paused, stopping, completed, cancelled, failedWhether the session can continue and which user controls are legal.
Activitynone, capturing-context, listening, recording, transcribing, agent-running, delivering, synthesizing, speaking, executingWhat resource or operation is active now.
Outcomecompleted, completed-with-fallback, rejected, unavailable, ambiguous, cancelled, failedStable terminal result for clients and compatibility views.

SessionManager permits one foreground interactive session initially and exclusively leases microphone and speaker resources. A second capture returns busy; it never steals or implicitly cancels another session. Status stores mode, lifecycle, activity, revision, coarse input/output/agent categories, cancellability, timestamps, and stable failure codes—but never transcript, selection, raw context, paths, titles, app/window/session identifiers, clipboard data, commands, secrets, or approval details.

Approval capabilities are closed values: read-context, draft, insert, execute, send, modify, and delete. Approval binds the exact destination, operation digest, context fingerprint, adapter, agent session, voice session, and expiration, and is consumed atomically at most once. Spoken confirmation alone cannot authorize execute, send, modify, delete, or unrestricted command execution in the first release. Agent output and truthy insertion results never create authority; dispatched-unconfirmed can represent non-consequential text delivery but cannot authorize an action.

Optional Daemon Protocol

The daemon uses a private AF_UNIX stream socket at $XDG_RUNTIME_DIR/linux-speech-tools/control-v1.sock. It is an optional host for the same SessionManager, not a separate product path.

  • Four-byte big-endian frame length followed by UTF-8 JSON; maximum frame size 1 MiB.
  • Required protocol_version: 1, request ID, bounded deadlines, and one response per request.
  • Private owned parent mode 0700, socket mode 0600, and rejection of pre-existing symlink/FIFO/non-socket paths.
  • Validate Linux SO_PEERCRED and require the current UID.
  • session.start returns a random volatile owner token. Mutating calls require it; same-UID credentials alone do not authorize another local client to approve, stop, or steal a session.
  • Transcript and context events require the owner token and are excluded from general status subscriptions.
  • Request IDs are idempotent within a bounded daemon-instance cache.
  • No TCP listener, no broad process discovery, and no required persistent database.
health.get          capabilities.get   status.get
events.subscribe    session.start       session.stop
session.cancel      session.pause       session.resume
session.approve     session.deny        daemon.shutdown

A normal client disconnect does not cancel a running session unless cancel_on_disconnect was explicitly selected. Daemon restart invalidates all approvals and owner tokens. In auto mode, a missing daemon uses the in-process host; in require mode it returns unavailable without silent downgrade.

Security Notes

  • Audio: local by default; remote use requires explicit provider and visible indicator. No microphone audio in logs, metrics, or action audit.
  • Context: least privilege, per-item origin and expiry, bounded content, explicit preview, and no implicit clipboard/history read.
  • Agents: untrusted output; bounded decoding and display; no instructions from model output become authorization.
  • Actions: capability-based approvals bound to an exact operation digest and destination; no reusable blanket voice approval.
  • Delivery: original-target verification before and during placement; ambiguity locks retries and submission.
  • Daemon: private runtime directory, Unix peer credentials, no TCP listener by default, strict framed schema, single-user scope, deadlines, quotas, and process-group cleanup.
  • Local client authority: same-UID socket access is necessary but insufficient; volatile per-session owner tokens bind mutating controls and approvals.
  • Browser: minimal active-tab permissions, origin display, navigation invalidation, no history capture, no incognito by default.
  • Remote: no secrets in argv/status/logs; system secret storage or file descriptor input; TLS; explicit host allowlist where feasible.
  • Licensing: preserve MIT implementation; study AGPL systems but do not copy source into this process. Prefer process/protocol interoperability.
  • Supply chain: retain locked Python dependencies, versioned installers, immutable release assets, tested native-package promotion, and clean-tree release gates.

Architecture Notes

  • VoiceSession owns policy and lifecycle, not platform subprocess details.
  • Existing InsertionSession remains the text-delivery authority; it is composed, not duplicated.
  • Context providers return data and provenance but never select agents or authorize actions.
  • The permission broker receives proposed capabilities but never interprets model text as approval.
  • Agent adapters translate provider protocols but do not decide product safety policy.
  • The first CLI is in-process so domain semantics can stabilize before introducing IPC.
  • The same SessionManager is hosted by both standalone and daemon operation; trace-equivalence tests prevent semantic drift.
  • The later daemon optimizes warm models and continuity; it is not required for safe fallback.
  • Status schemas are versioned and privacy-safe. Rich content stays in the initiating client unless explicitly handed off.
  • Compatibility entry points remain until telemetry and release notes prove migration; no mass rename breaks current users.

Open Decisions

  • Product name and command: this plan recommends the existing project name with one lst CLI during beta. Decide whether the user-facing name should remain Linux Speech Tools or become Linux Voice Workspace before a stable unified release.
  • Daemon default: recommend opt-in/on-demand through the first acceptance cycle, then consider default user-service activation only if startup, idle cost, and recovery evidence pass.
  • First browser: recommend Chromium first for the initial active-page bridge, followed immediately by Firefox using the same protocol. Confirm whether simultaneous v1 support is a release requirement.
  • First non-Codex agent: strategy order recommends Claude Code, then Open Interpreter, Goose, and OpenClaw. Confirm based on the user's daily workflow before implementing adapter two.
  • Action audit retention: choose the default duration for metadata-only local action records. Recommend 30 days with immediate clear/export controls and no transcript or raw context.
  • Remote ASR authentication: choose system secret-service integration versus a private environment/config reference for v1. Never store bearer tokens in the normal config or status file.
