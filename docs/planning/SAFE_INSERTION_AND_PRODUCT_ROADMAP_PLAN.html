Purpose / Problem

The repository has strong speech infrastructure, but three planning documents are at different lifecycle stages and should not compete as equal initiatives. The June code audit is historical closure work, the pluggable ASR architecture is implemented except for its real-audio Spanish gate, and the IBus investigation describes a substantial optional platform project. Treating all three as active product roadmaps would continue concentrating effort below the assistant and developer-workflow layer.

This plan produces five concrete outcomes in dependency order:

  1. Close the historical audit with an evidence-backed resolution ledger and extract only genuinely open live issues.
  2. Run the Argentinian-first LATAM Spanish benchmark and move Parakeet to maintenance mode without changing the default engine automatically.
  3. Stabilize and prepare the existing lst-dictate work for release.
  4. Build a reusable, target-bound insertion safety layer and a GNOME focus provider.
  5. Ship at least one context-aware assistant vertical slice before considering a narrowly scoped final-only IBus prototype.
North star: reliable target identity + safe insertion session + context-aware agent workflows. IBus remains a conditional transport investment, not the product center.

Chosen principles

  • Close before expanding. Resolve historical documents and the benchmark before creating new platform code.
  • Policy above transport. Target identity, revisions, fallback and submit safety belong to an insertion session, not to ydotool, clipboard or a future IBus backend.
  • Fail closed. Focus drift, stale revisions and ambiguous post-dispatch results cannot trigger reinsertion or Enter.
  • Preserve behavior in small migrations. Wrap current renderers first; do not rewrite every output backend simultaneously.
  • Real-environment gates. Microphone, ASR quality and GNOME focus behavior require real recordings and a live desktop.
  • Conditional IBus. Build it only if measured daily friction remains after P1 and an interoperability route is unavailable.

Scope Boundaries

In scope

  • Audit-document resolution and issue extraction.
  • Focused review and release readiness for current lst-dictate behavior.
  • Execution and recording of the existing LATAM ASR benchmark gate.
  • A backend-neutral insertion result and session state machine.
  • Migration of prompt submission into that session.
  • A GNOME Shell D-Bus focus provider with session-scoped identity and focus generation.
  • GNOME 49/50 compatibility verification before advertising support.
  • Selection and separate planning of one differentiated assistant vertical slice.
  • Privacy-preserving local measurements used for the later IBus decision.
  • Conditional IBus diagnostics and final-only prototype after all gates.

Explicitly out of scope

  • IBus preedit and surrounding-text editing.
  • Automatic IBus preference or generic compositor routing.
  • KDE, wlroots and broad non-GNOME IBus support.
  • Additional local ASR engines or language-based engine auto-selection.
  • Two-tier streaming ASR.
  • Changing faster-whisper as the default merely because Parakeet passes a personal benchmark.
  • Sending messages to Vocalinux maintainers without explicit approval.
  • Publishing a release or creating external issues without the normal explicit release/issue authorization at execution time.
  • A complete design for email, calendar, terminal automation, remote ASR or phone control; those follow the P2 vertical-slice decision.

Target Architecture

Insertion boundary

FasterWhisperSession / future agent workflow
                  |
                  v
          InsertionSession
   session id · revision · target token
   result state · fallback · submit policy
        /             |              \
       v              v               v
synthetic transport  clipboard/overlay  future IBus/application API
ydotool/xdotool      non-inserting      final commit or stronger ack

The initial contract is conceptual; exact Python names may vary while preserving these operations:

class InsertionSession:
    def update(self, text: str, revision: int) -> InsertionResult: ...
    def finalize(self, text: str, revision: int) -> InsertionResult: ...
    def submit(self) -> InsertionResult: ...
    def cancel(self) -> InsertionResult: ...
    def close(self) -> None: ...

Result contract

StateMeaningAutomatic reinsertion?Submit eligible?
confirmed-insertedA future backend provides genuine target acknowledgement.NoYes, only with unchanged target and explicit submit policy.
dispatched-unconfirmedA synchronous synthetic command succeeded, but application receipt is not provable.NoOnly when explicitly requested, the command returned success, and the target token still matches.
clipboard-fallbackTranscript was copied, not inserted.NoNo
failed-before-dispatchNo insertion action was issued.Allowed only through policy-selected safe fallback.No
ambiguous-after-dispatchAn action may have reached the target, but completion is unknown.NeverNever
rejectedSafety policy rejected the operation, such as locked session or focus drift.Clipboard only if safe.No
unavailableBackend capability is absent.Allowed before dispatch according to configured fallback.No
staleRevision is older than or conflicts with current session state.NoNo
cancelledSession was explicitly cancelled or closed before finalization.NoNo

Result objects carry backend, revision, target-token match and non-sensitive diagnostics. They never contain transcript text. finalize() is idempotent for the same revision and cannot issue the final insertion twice.

GNOME focus identity

The existing D-Bus client expects org.linux_speech_tools.Focus.GetFocus. The provider should return a versioned payload containing:

{
  "schema_version": 1,
  "shell_session_id": "random-per-extension-enable",
  "window_sequence": 1234,
  "focus_generation": 57,
  "locked": false,
  "app_id": "org.gnome.Terminal",
  "wm_class": "org.gnome.Terminal",
  "title": "optional secondary metadata",
  "pid": 12345,
  "window_id": "gnome:<shell-session-id>:<window-sequence>"
}
  • Meta.Window.get_stable_sequence() supplies a per-window sequence.
  • The extension creates a new random shell-session ID whenever enabled.
  • notify::focus-window increments the focus generation.
  • The client requires the window ID and captured generation to remain unchanged.
  • A focus-away-and-back cycle therefore invalidates a live insertion session rather than silently resuming it.
  • A missing provider, disabled extension, lock state or malformed response fails closed.
  • Title may assist classification but is never the primary identity and must not be persisted in status or metrics.

Test Strategy

P0 assertions

  • Every audit ID appears once and has one allowed resolution plus non-empty evidence.
  • All extracted open Critical/High findings are visible outside the historical audit.
  • lst-dictate process-tree teardown signals only same-UID, start-token-validated descendants deepest-first.
  • Finalization timeout/error evidence never produces a success notification.
  • No callback reaches a closed renderer after bounded session shutdown.
  • Focus drift never produces Backspace, paste or Enter in the new target.
  • The benchmark manifest validates; every clip is scored by both available engines or has an explicit per-clip error.
  • The result report contains environment, corpus composition, overall/per-accent WER, code-switch review and final decision.

P1 unit and integration assertions

  • Revision ordering: stale or duplicate updates have no unintended transport call.
  • Finalization: the same final revision is inserted at most once.
  • Ambiguity: no fallback reinsertion and no submit after ambiguous dispatch.
  • Pre-dispatch failure: safe configured fallback may run exactly once.
  • Clipboard/overlay/stdout: never submit.
  • Focus binding: shell session, window ID and generation must match and session must be unlocked.
  • Focus drift: permanent clipboard fallback even after returning to the original window.
  • Provider restart: old target tokens are invalid.
  • Extension lifecycle: D-Bus object exists only while enabled and all signal/name ownership is released on disable.
  • Status/log privacy: no transcript, clipboard text or window title is serialized in result metrics.
  • Compatibility: current CLI/output defaults and existing X11 behavior remain unchanged.

Security Notes

  • Text is sensitive. Transcript, clipboard content and prompt text must not enter status files, metrics or logs.
  • Titles are sensitive metadata. Window title is secondary classification data only; do not persist it in result metrics.
  • Target identity is session-scoped. Combine a fresh Shell-session nonce with Mutter's stable sequence; never treat the sequence as globally permanent.
  • Focus generation prevents unsafe resume. Any focus transition invalidates the session, even if the original window later returns.
  • Lock state fails closed. A locked session, disabled provider or missing D-Bus service cannot authorize destructive typing or submit.
  • Submit is a side effect. Only the insertion session may issue it, and never after clipboard-only, stale, rejected, failed or ambiguous states.
  • Ambiguity is terminal. Once a transport may have dispatched text, do not try another inserting transport automatically.
  • Benchmark privacy. Keep personal recordings out of git by default; publish only consented/sanitized material and aggregate results.
  • D-Bus exposure. The focus provider is read-only and user-session scoped, but any same-user process may call it; return the minimum useful metadata and no transcript.
  • Extension resilience. All D-Bus names, exported objects and signals must be released on disable to avoid stale focus authority.
  • Licensing. Do not copy Vocalinux implementation, comments or tests. Implement from official platform APIs and this project's independent behavioral specification.
  • P2 permissions. Agent, terminal, email, calendar and external messaging actions require explicit capability boundaries in the separate P2 plan.

Architecture Notes

  • ASR remains independent. Audio capture and recognition emit text; they do not know ydotool, clipboard, GNOME or IBus.
  • InsertionSession is policy. It owns session/revision/target/finalization/fallback/submit state.
  • Transports are mechanisms. Existing renderer logic is adapted rather than allowed to decide global workflow safety independently.
  • Focus provider is evidence. It supplies current desktop facts; the insertion policy decides whether they authorize an action.
  • Output modes remain stable. Clipboard, overlay, paste, live-type and stdout retain their user-facing meanings.
  • No IBus types leak into P1. The result/session vocabulary must support IBus later without depending on it now.
  • Python 3.8 compatibility remains. New core modules avoid 3.9+-only annotation syntax unless project metadata is intentionally changed.
  • GNOME support is evidence-based. The extension now passes an isolated GNOME Shell 50.1 runtime/lifecycle smoke; older declared versions and live desktop application behavior remain manual validation gates.
  • Historical documents stop driving work. The audit becomes evidence, the ASR proposal becomes a result record, and only approved implementation plans govern new changes.

Phase rollback boundaries

  • P0: primarily documentation and evidence; benchmark conclusions can be amended without runtime rollback.
  • P1 insertion: keep a compatibility adapter until the full manual matrix passes, enabling a narrow transport-policy rollback.
  • P1 GNOME: provider absence already produces a fail-closed fallback; disabling the extension is the immediate rollback.
  • P2: each external capability must be independently disabled.
  • P3: IBus remains explicit and optional, so rollback is backend removal/disable with no default migration.

Open Decisions

  • OD-1 — Resolved. The local release candidate is v1.1.0 because the accumulated pluggable ASR, prompt dictation and lifecycle work is feature-level. Publication remains a separate approval gate.
  • OD-2 — Benchmark corpus publication. Recommended: keep raw personal audio private, commit aggregate results and optionally a sanitized reference manifest. A public LATAM claim requires consented recordings representing MX/CO/CL, not imitated accents.
  • OD-3 — Resolved. The first P2 slice is a repository-aware spoken/text request through a strictly read-only Codex CLI adapter, with bounded stdout/safe insertion and optional speech response.
  • OD-4 — GNOME support range. Recommended: preserve 45–48 intent, add 49/50 only after live or reproducible validation, and do not claim versions that merely pass metadata parsing.

None of the remaining open decisions blocks P0 audit closure or corpus preparation. The release publication approval gate remains closed, OD-2 blocks a public regional claim, and OD-4 blocks extension support declarations beyond the validated evidence.
