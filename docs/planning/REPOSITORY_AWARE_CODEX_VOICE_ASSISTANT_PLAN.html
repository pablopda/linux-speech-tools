Implementation Plan: Repository-Aware Codex Voice Assistant

Living document — last amended 2026-08-10. Open in a browser; amend, don't rewrite.

Purpose / Problem

Deliver the first differentiated assistant slice from the product roadmap: capture or accept one developer request, run one explicitly selected local agent against the current repository, return a bounded answer, and place and/or speak that answer through existing safe output paths. The success metric is one read-only repository question completed end to end without mutating the repository, exposing prompt text in process arguments or status files, or inserting into a changed target.

Approach

Use the locally installed Codex CLI's documented non-interactive codex exec mode as the single initial adapter. Invoke it with an ephemeral session and an explicit read-only sandbox, pass the request on standard input, set the selected repository as its working root, bound run time and output size, and treat all failures as non-delivery. Capture the original desktop target before the agent starts and use the existing InsertionSession contract for any response placement after the long-running call. TTS receives the answer through standard input via say-read -.

A direct OpenAI API client was rejected for the first slice because it would duplicate Codex repository tooling and introduce separate key/model management. A generic arbitrary shell-command adapter was rejected because it weakens the explicit permission boundary. Workspace-write Codex mode is deferred: this slice answers questions only and cannot approve mutations or external messages.

Implementation Steps

DONE 1. Select the vertical slice and agent.

Selected journey: spoken or textual repository question → read-only Codex CLI → bounded answer → stdout, safe insertion, and/or speech.

Done when: the adapter and user-visible success metric are explicit and no unresolved product choice blocks implementation.
DONE 2. Implement the bounded Codex adapter.
  • Discover codex without invoking a shell.
  • Use --ask-for-approval never with exec --ephemeral --ignore-user-config --ignore-rules --sandbox read-only --color never.
  • Send the request over stdin and capture stdout/stderr privately.
  • Terminate the whole child process group on timeout or interruption.
  • Drain stdout incrementally, retain only a bounded binary prefix, tolerate invalid UTF-8, and return a generic redacted error.
Done when: unit tests prove exact argv, stdin-only prompt transfer, timeout tree cleanup, output bounds and redacted errors.
DONE 3. Add text and speech request collection.

Accept exactly one prompt from an argument-safe stdin/text interface or collect finalized utterances with the existing engine-agnostic STT session.

Done when: text mode is hermetic and speech mode assembles final utterances without emitting partial text to the agent.
DONE 4. Add response delivery.

Support stdout, clipboard, paste, live-type and overlay via InsertionSession; optionally pipe the answer to say-read -.

Done when: focus drift and ambiguous insertion never retry or submit, and TTS failure cannot change successful text-delivery evidence.
DONE 5. Add launcher, diagnostics and installation.

Create lst-agent, a side-effect-light --check, configuration allowlist entries and installer/package coverage.

Done when: the launcher works from a checkout and packaged root, diagnostics do not contact Codex, and installer dry-runs include it.
DONE 6. Validate the end-to-end slice.

Exercise a fake adapter in automation and an explicit authenticated read-only Codex run manually; record no repository mutation before/after.

Done when: a repository question yields a bounded answer, the chosen output succeeds, focus drift fails closed, and git status is unchanged by the agent run.

Test Strategy

  • Patch process creation and prove prompt text appears only on stdin, never argv, status or error output.
  • Prove read-only/ephemeral flags, repository-root validation, no shell invocation and whole-process-group timeout cleanup.
  • Prove nonzero exit, empty answer, oversized answer and malformed environment values fail safely.
  • Prove invalid UTF-8 cannot crash output handling and excess stdout is drained without unbounded retention.
  • Use fake STT final callbacks to verify multi-utterance assembly and session failure propagation.
  • Reject symlinked, non-regular and oversized request files through one bounded file descriptor.
  • Use fake insertion transports to verify focus-bound finalization, underlying terminal-identity refusal and no Enter.
  • Use fake TTS to prove stdin transfer, timeout/interrupt cleanup and independence from insertion success.
  • Run existing P1 insertion, session, launcher, installer and package suites for regression coverage.

Security Notes

  • The user request and repository contents are sent to the user's authenticated Codex service. Each run is an explicit opt-in action.
  • The initial adapter pins read-only mode and a non-interactive never approval policy, while ignoring user/project execpolicy rules. No flag enables workspace writes, external messaging or terminal mutation.
  • Prompt text travels on stdin, not argv; responses are memory-only unless the user explicitly chooses clipboard/insertion.
  • No credential is parsed, logged or stored by this project. Codex CLI owns authentication, and ephemeral mode suppresses local session rollout persistence.
  • Target identity is captured before the remote call and must still match before insertion. The workflow never sends Enter.
  • Untrusted model output uses direct paste/live-type only for exact allowlisted dedicated text-editor identities with a stable verified target; terminals, IDEs, browsers and unknown identities degrade to clipboard.
  • stderr and exceptions are reduced to generic error classes; transcript, path, title and agent output are excluded from status.

Architecture Notes

RepoAgentAdapter owns only agent execution. Request collection and response delivery depend on narrow protocols so future supported local or remote adapters do not enter STT or insertion code. InsertionSession remains the sole authority for desktop placement. The workflow never parses model reasoning or command events; it consumes only the documented final message stream.

Risks & Rollback

  • Codex CLI behavior/version drift → exact capability check, conservative failure and mocked contract tests.
  • Long, wedged or interrupted run → bounded timeout plus validated process-group termination.
  • Repository data leaves the machine → explicit user action and documentation; no background calls.
  • Focus changes while waiting → original-target generation check and clipboard fallback.
  • Rollback: remove the isolated launcher/package and assistant module; P1 dictation/output paths remain unchanged.

Open Decisions

None. The active objective approves the roadmap's recommended first slice; Codex CLI is the selected read-only adapter, stdout is the default response output, and speech/output features remain explicit flags.
